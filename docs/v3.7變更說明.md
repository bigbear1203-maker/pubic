## 三個關鍵修改的細節

### 1. 未完成 K 棒（`_trim_incomplete_bar`）

盤中執行時，yfinance 回傳的最後一根 K 棒尚未收盤，`Close` 是當下成交價。而隔日模型的核心特徵 `intraday_return = (Close - Open) / Open` 訓練時看到的全是完整交易日。

**v3.7 之後**：盤中執行會剔除該 K 棒，並在畫面上明說。這代表 **8/28 盤中跑的結果，會等同於 8/27 收盤後跑的結果**——這正是測試 [7] 驗證的等價關係。

一個重要的例外：**「今日」模型不套用這個剔除**。它的特徵只用今天的開盤價與昨日（含）以前 `shift(1)` 的值，從不碰今天的 `Close`，所以盤中執行時反而需要含當日 K 棒的完整序列才拿得到今天的開盤價。兩個模型在這件事上的需求相反，v3.7 分開處理。

```python
hist, bar_trimmed, live_price = _trim_incomplete_bar(hist_raw, ticker_symbol)
# 隔日模型 / 技術面 / 籌碼面 → 用 hist（已剔除）
# 今日模型 → 用 hist_raw + last_bar_complete=not bar_trimmed
```

### 2. Wilson 信賴下限取代固定 55%

舊規則 `準確率 < 55% 就封鎖` 與樣本數無關，兩個方向都會判錯：

| 情境 | 舊規則 | v3.7 |
|---|---|---|
| n=60，準確率 56% | 放行 | **擋下**（需 ≥62.7%） |
| n=2000，準確率 53.5% | 擋下 | **放行**（需 ≥53.1%） |

需要澄清的是：這道關卡**不保證**能擋掉 2891C 那筆訊號。若它的樣本數確實夠多，74% 是會通過的，而且應該通過。真正該擋的是它的成因（未完成 K 棒）。Wilson 修的是「幾筆樣本算出來的」這個資訊在 v3.6 完全遺失的問題。

### 3. EV 影子決策（刻意不取代原本的規則）

新增 `EV_Decision` 欄位，用「扣掉台股來回成本 0.471% 後期望值是否為正」判斷方向，**與既有的 `Strategy_Decision` 並行記錄**。

為什麼不直接換掉：在累積足夠樣本證明哪一種規則實際表現較好之前，片面改掉你的交易邏輯是不負責任的。`log_review.py` 會同時統計兩者「有出手時」的命中率，讓資料決定。

## Excel 欄位變動

v3.7 的欄位結構與 v3.6 不同，會**自動另存新檔**（沿用既有保護機制），不會覆蓋舊紀錄。

新增欄位分四類：

**執行情境**（沒有這些就無法事後區分盤中/盤後紀錄）
`是否盤中執行`、`已剔除未完成K棒`、`執行當下價格`、`資料落後天數`、`資料是否停滯`、`跳過原因`、`交易日曆提醒`

**模型可信度**
`隔日_邏輯迴歸_樣本數`、`隔日_RF_樣本數`、`今日_邏輯迴歸_樣本數`、`今日_RF_樣本數`、`隔日_邏輯迴歸_準確率信賴下限(%)`、`隔日_RF_準確率信賴下限(%)`、`今日模型是否已知結果`

**影子決策**
`EV_Decision`、`EV_採用模型`、`EV_淨期望值(%)`、`EV_來回成本(%)`、`EV_原因`

**事後回填**（由 `log_review.py --write-back` 填入）
`實際目標日收盤`、`實際報酬(%)`、`實際方向`、`是否命中_邏輯迴歸`、`是否命中_RF`、`是否命中_綜合分數`、`回填時間`

## 每日流程

```bash
# 1. 收盤後（15:00 之後）執行分析
python claude_stock_analyzer_v3.7.py 2330.TW 2408.TW 1303.TW

# 2. 回填前一日的實際結果，並看目前累積的驗證統計
python tools/log_review.py stock_analysis_log_v3.7.xlsx --write-back
```

`--write-back` 只補空白欄位、不覆蓋既有值，所以可以每天重複執行。

## 沒有改的東西，以及為什麼

| 沒改 | 原因 |
|---|---|
| 手寫的 `_logistic_regression_fit` | 換成 sklearn 會改變所有歷史數字的可比較性。等累積夠樣本、確定要留這個模型再說 |
| 機率校準（Platt / isotonic） | 目前樣本數（n=20）不足以 fit 校準曲線，硬做只會 overfit |
| `compute_risk_reward` 的 1.5×/2× ATR | 這兩個倍數確實沒有回測支撐，但要改成什麼同樣沒有依據。先記錄、後驗證 |
| `dual_model_decision` 的 58% 門檻 | 改成 EV 影子決策並行記錄，讓資料決定，不片面替換 |
| `tw_active_stocks_predictor` 的線性外推 | 程式自己已誠實標註為「動能外推、非機器學習」。它預測的是活躍度不是報酬，定位本來就不同 |

這些都屬於診斷報告 §5 的「第三階段」——**依證據決定**，不是現在就動。
