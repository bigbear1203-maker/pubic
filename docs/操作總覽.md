## 日常：點兩下就好

資料夾裡有四個批次檔，**直接用滑鼠點兩下**，不用開終端機、不用記路徑：

| 批次檔 | 做什麼 |
|---|---|
| **每日執行.bat** | 每個交易日收盤後點它（15:00 之後） |
| **查看績效.bat** | 看模擬績效 |
| **環境自檢.bat** | 換版後檢查有沒有問題 |
| `stock.bat` | 給終端機用的：`stock.bat daily`、`stock.bat check` |

批次檔內第一行是 `cd /d "%~dp0"`，會自動切到它自己所在的資料夾，
所以**不論你從哪裡執行都不會出錯**。

### 如果你習慣用終端機

```powershell
cd "D:\Claude\weather\股票分析"     # 這一行不能省
python stock.py daily
python stock.py report
```

⚠ 最常見的錯誤是 `can't open file 'stock.py'` —— 那不是程式壞了，
是你所在的資料夾不對。用批次檔就不會遇到。

`daily` 會依序做四件事：活躍股篩選 → 逐檔完整分析 → 模擬推進一天 → 回填前一日實際結果。
週五執行時會**額外**另存一份 `模擬週報_YYYY-MM-DD.xlsx`（不出清部位）。

## 事件日曆（`events`）

### 它做什麼

推算兩類**排程事件**，告訴你哪幾天波動會偏大：

| 事件 | 規則 | 為什麼重要 |
|---|---|---|
| 期貨結算日 | 到期月第三個星期三，休市則**順延** | 現貨受期貨部位調整影響，日內波動放大 |
| 期貨結算前一交易日 | 結算日的前一個交易日 | 調整壓力通常提前一天出現 |
| 月營收公布截止日 | 每月 10 日，非交易日則順延 | 上市櫃須於 10 日前公布上月營收，個股易跳空 |
| 月營收公布後首個交易日 | 截止日的次一交易日 | 盤後公布的營收，隔天才反應在價格上 |

全部是純日曆推算，**不需要網路**。假日清單直接從 `claude_stock_analyzer_v3.7.py`
的 `TW_HOLIDAYS` 讀出來，不另外複製一份 —— 兩份清單一定會走鐘，而走鐘時
不會有任何錯誤訊息，只會安靜地把日期算錯。

除權息需要個股資料（要連網），預設不查，用 `--with-dividends 2330 2454` 才會抓。

### 它刻意不做什麼

```
✗ 不進模型、不加特徵
✗ 不改評分、不改買賣建議
✗ 不動 Excel 欄位
```

這是現階段**故意的**，不是還沒寫。理由：

已排程事件的日期是公開資訊，市場早就定價完畢，對「漲跌**方向**」幾乎沒有
預測力；有預測力的是「**波動大小**」。而且樣本數太少 —— 期貨結算日一年只有
12 天，五年 60 個樣本。在 60 個樣本上估效應，跟 2891C 那個 `n=40` 是同一個
問題：`wilson_lower_bound()` 永遠爬不過 50%。

加事件特徵 = 維度變多、樣本沒變多 = **in-sample 變好看、walk-forward 變差**。

所以事件日曆的正當用途是**風險管理**（那天要不要開新倉、停損要不要放寬），
不是預測漲跌。

### 怎麼用

```bat
python stock.py events                  未來 14 天
python stock.py events --days 30        未來 30 天
python stock.py events --month 2026-10  指定月份完整事件表
python stock.py events --stats          事件日 vs 一般日的實際表現
```

不帶參數跑 `python stock.py` 時，總覽畫面也會直接列出未來 7 天的事件日。

### `--stats` 在算什麼

拿紀錄檔裡**已經回填實際結果**的資料，依「預測目標日」是不是事件日切成兩組，
比較：

- 平均**絕對**報酬（波動的代理指標）與標準差
- 平均報酬、最好、最差
- 各模型命中率

用的是「預測目標日」而不是「執行日」—— 實際報酬是在目標日實現的，用執行日
去對事件會整個錯開一天。

兩邊樣本都不到 30 筆時，它會明講**樣本數不足、不要當成證據**，而不是給你一個
看起來很像結論的數字。

### 驗證的順序

1. 每天照常 `python stock.py daily`，什麼都不改
2. 累積一個月後跑 `python stock.py events --stats`
3. 事件日波動**明顯**較大 → 才考慮「事件日不開新倉」或「放寬停損倍數」
4. 就算成立，也**不要**把事件放進模型當特徵（見上面的樣本數問題）

## 為什麼要有 `stock_settings.json`

成本參數原本在 `claude_stock_analyzer` 和 `paper_trading` **各定義一次**。
你哪天換券商、只改了一邊，就會出現「操作建議算的成本」跟「模擬扣的成本」不一致 —— 而且**不會噴任何錯誤**。

現在改一個地方，兩邊同步：

```json
"券商與稅費": {
  "fee_discount": 0.6,          ← 你券商的折扣，28折就填 0.28
  "securities_tax_pct": 0.3     ← 當沖改 0.15
}
```

找不到這個檔案時，各程式會用內建預設值，不會出錯。

## 為什麼要有 `check` 和 `archive`

**因為混版執行已經害你壞過一次資料。**

2026-08-31 的紀錄檔出現表頭是舊版（101 欄）、資料是新版（103 欄）的錯位，從第 13 欄開始每一欄的值都對到錯誤的名稱上 —— `程式版本` 欄位裡是斜率數字、`實際報酬(%)` 欄位裡是 `3.7`。

這種錯位**不會噴任何錯誤**，但 `log_review` 之後所有統計都會算在錯的欄位上，而你看不出來。

- `check` 會比對紀錄檔的欄位結構，不符就叫你去修
- `archive` 把舊版程式移出主資料夾，從源頭避免混版
- analyzer 也加了寬度防線：偵測到檔案被寫壞就改寫新檔，不再往裡面 append

**每次換新版程式之後，先跑一次 `python stock.py check`。**

## 換版流程

```powershell
# 1. 覆蓋新的程式檔
# 2. 自檢
python stock.py check
# 3. 若提示有舊版殘留
python stock.py archive
# 4. 若提示紀錄檔欄位不符
python stock.py repair
# 5. 再檢一次，確認「全部正常」
python stock.py check
```
