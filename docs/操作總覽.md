## 日常：只需要記兩個指令

```powershell
cd "D:\Claude\weather\股票分析"

python stock.py daily      # 每個交易日收盤後（15:00 之後）
python stock.py report     # 想看模擬績效時
```

`daily` 會依序做四件事：活躍股篩選 → 逐檔完整分析 → 模擬推進一天 → 回填前一日實際結果。
週五執行時會**額外**另存一份 `模擬週報_YYYY-MM-DD.xlsx`（不出清部位）。

## 全部指令

| 指令 | 做什麼 | 什麼時候用 |
|---|---|---|
| `daily` | 篩選 → 分析 → 模擬 → 回填 | **每個交易日收盤後** |
| `report` | 模擬績效（策略比較、週績效、成本警示） | 隨時 |
| `status` | 目前現金、持股、待成交單 | 隨時 |
| `review` | 回填實際結果、更新命中率統計 | `daily` 已含，單獨補跑時用 |
| `advice` | 把操作建議欄位補到既有紀錄檔 | 舊紀錄沒有這些欄位時 |
| `compare` | 比較活躍股預測 v2.1 / v3.0 / v3.1 | 想驗證哪一版選股較好時 |
| `settle` | 結算出清模擬部位並印完整報告 | 想收尾一輪模擬時 |
| `repair` | 修復欄位錯位的紀錄檔 | `check` 提示欄位不符時 |
| `check` | 環境自檢：套件、檔案、版本、設定、紀錄檔 | **每次換版後** |
| `archive` | 把舊版程式移到 `舊版/` | 換版後清理 |
| `sim-init` | 依設定檔建立新的一輪模擬 | 重開一輪時 |

不帶參數執行 `python stock.py` 會列出上表與目前狀態 —— 用 VS Code 的 ▶ Run 按鈕也看得到東西。

## 為什麼要有 `stock_settings.json`

成本參數原本在 `claude_stock_analyzer` 和 `paper_trading` **各定義一次**。
你哪天換券商、只改了一邊，就會出現「操作建議算的成本」跟「模擬扣的成本」不一致 —— 而且**不會噴任何錯誤**。

現在改一個地方，兩邊同步：

```json
"券商與稅費": {
  "fee_discount": 0.6,          ← 你券商的折扣，28折就填 0.28
  "securities_tax_pct": 0.3     ← 當沖改 0.15
}
```

找不到這個檔案時，各程式會用內建預設值，不會出錯。

---

## 為什麼要有 `check` 和 `archive`

**因為混版執行已經害你壞過一次資料。**

2026-08-31 的紀錄檔出現表頭是舊版（101 欄）、資料是新版（103 欄）的錯位，從第 13 欄開始每一欄的值都對到錯誤的名稱上 —— `程式版本` 欄位裡是斜率數字、`實際報酬(%)` 欄位裡是 `3.7`。

這種錯位**不會噴任何錯誤**，但 `log_review` 之後所有統計都會算在錯的欄位上，而你看不出來。

- `check` 會比對紀錄檔的欄位結構，不符就叫你去修
- `archive` 把舊版程式移出主資料夾，從源頭避免混版
- analyzer 也加了寬度防線：偵測到檔案被寫壞就改寫新檔，不再往裡面 append

**每次換新版程式之後，先跑一次 `python stock.py check`。**

---

## 換版流程

```powershell
# 1. 覆蓋新的程式檔
# 2. 自檢
python stock.py check
# 3. 若提示有舊版殘留
python stock.py archive
# 4. 若提示紀錄檔欄位不符
python stock.py repair
# 5. 再檢一次，確認「全部正常」
python stock.py check
```
