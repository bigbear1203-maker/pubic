# 活躍股預測程式 v2.1 vs v3.0 比較

**結論先講**：**v3.0 明顯比較好，但好在「選出的股票確實比較活躍、名單比較穩定」，不是好在「選出的股票比較會漲」。** 這兩支程式都不是報酬預測工具，它們自己的 docstring 也都誠實說明了這一點。

要判斷「哪個選的股票比較會漲」，必須拿真實資料測——用 `tools/compare_predictors.py`。

---

## 一、v3.0 確實改進的地方

### 1. 排除 ETF / ETN / 權證 / 特別股 ★ 影響最大

`is_common_stock()` 只保留 4 碼純數字代碼，再用名稱關鍵字做第二層排除。

**用你真實的 log 驗證**：19 檔分析過的標的中，v3.0 會排除 4 檔，而**這 4 檔正好就是製造問題的那 4 檔**：

| 被排除 | 在你 log 裡造成的問題 |
|---|---|
| `020020.TW` | 模型完全無輸出（ADX、兩個機率全是 NaN），卻仍給綜合分數 0、結論「中性」 |
| `006204.TW` | 目前股價欄位是空的，仍照常輸出上漲機率 62.0% |
| `00684R.TW` | 資料基準日停在 8/26 不動（同批其他檔都是 8/27） |
| `2891C.TW` | 回報 77.3% 準確率（全場最高、遠離其餘中位數 51~52%），**並發出整份紀錄唯一的 Sell 訊號** |

15 檔普通股沒有一檔出現這些問題。這不是巧合——這些標的的資料結構本來就跟普通股不同（ETF 沒有財報、反向 ETF 的價格行為不同、特別股上市時間短且流動性低），拿同一套模型硬套本來就會出事。

### 2. 回看天數 5 → 30 天

v2.1 用 5 個交易日做線性回歸求斜率。5 個點的迴歸幾乎不含資訊，斜率主要反映的是最後一天的雜訊。

**實測（合成全市場面板，1,020 檔 × 45 天）**：每天重跑一次，前 10 名與前一天的重疊檔數

| | 平均延續檔數 |
|---|---|
| v2.1 | **3.5 / 10** |
| v3.0 | **5.5 / 10** |

v2.1 的名單每天換掉三分之二。對於一個要拿來當「明天觀察清單」的工具，這個穩定度太低了。

### 3. log1p + 分位數 clipping

台股成交金額跨 4~5 個數量級（台積電單日成交值可能是小型股的一萬倍）。v2.1 直接對原始成交金額做 z-score，結果是分數幾乎完全由少數幾檔權值股決定，其餘 1,700 檔全部擠在同一個數值附近，等於沒有鑑別度。v3.0 先取 log 再標準化，這是處理長尾分布的標準做法，也是統計上最正確的一項修改。

### 4. 量比基準：expanding → rolling(10)

v2.1 在 5 天視窗內用 `shift(1).expanding().mean()`——第二天的「均量」只有 1 個樣本，第三天 2 個。這樣算出來的量比噪音極大。v3.0 用 `rolling(10, min_periods=3)`，基準穩定得多。

### 5. 最低歷史天數門檻（15 天）

v2.1 只要有 2 天資料就進榜，新上市或流動性極低的標的可以靠一天的異常量衝上前 10。

### 6. 活躍度延續性明顯較佳

**實測**：選出的標的在隔天的成交值，位於全市場的第幾百分位

| | 隔日成交值百分位 |
|---|---|
| v2.1 | 80.2 |
| **v3.0** | **96.7** |
| 基準：單純挑成交值最大的 10 檔 | 96.9 |

**這才是活躍度排序工具該被評價的指標，v3.0 大勝。**

但注意最後一列：v3.0 的表現跟「單純挑成交值最大的 10 檔」幾乎一樣（96.7 vs 96.9）。也就是說，那一整套加權、log、趨勢外推的複雜計算，在「找出活躍股」這件事上，跟最笨的做法效果差不多。這不是說 v3.0 沒用，而是說它的複雜度目前沒有換到對應的價值——值得你自己權衡。

## 二、v3.0 的問題

### 1. 趨勢項幾乎完全沒有作用 🟠

v3.0 的公式是 `predicted = recent_avg_score + slope × r2`。

**實測**：

| 項目 | 中位數 |
|---|---|
| `recent_avg_score` 絕對值 | 0.4312 |
| `slope × r2`（趨勢項）絕對值 | **0.0000** |
| 趨勢項 ÷ 主項 | **0.01%** |
| `trend_r2` | **0.0104** |

活躍度分數本身是高度隨機的序列，30 個點的線性擬合 R² 中位數只有 0.01。乘上 r2 之後，趨勢項基本上歸零。

**只用 `recent_avg_score` 排序，前 10 名與完整公式 100% 相同（10/10）。**

所以 v3.0 實際上不是在「預測」，而是在做「近 3 日平均活躍度排名」。

**這其實是好事**——用 r2 抑制不可靠的趨勢外推，正是應該做的事，結論就是「這個資料撐不起趨勢外推」。但你應該知道這件事：**v3.0 的「預測次日活躍度」名不副實，它是一個穩定的當前活躍度排名。** 名稱與實際行為不一致，日後容易誤導自己。

### 2. 4 碼規則擋不掉 0050、0056 🔴（測試時才發現）

```python
if len(sid) != 4:
    return False
```

台灣 ETF 代號 **0050（元大台灣50）、0056（元大高股息）、0051、0052、0057 都是 4 碼純數字**，會直接通過這個規則。而 0050 與 0056 正是全市場成交最熱的標的之一 —— 活躍度排名幾乎一定會抓到它們。

也就是說，v3.0 宣稱的「排除 ETF」對台股最重要的兩檔 ETF 完全無效。

**修法（v3.1）**：改用開頭字元判斷。上市普通股代號範圍 1101~9958，開頭一律是 1~9；以 `00` 開頭的都是指數化商品。

```python
if sid.startswith("00"):
    return False
```

### 3. 名稱關鍵字「期」會誤殺合法普通股 🟠

```python
excluded_keywords = ["ETF", "ETN", "權證", "反1", "正2", "槓桿", "反向", "期", "特別股"]
```

`群益期`（6024）是合法的上市普通股（期貨商），會被「期」誤殺。實測確認。

建議把 `"期"` 改成更精確的模式，例如只比對結尾或改用 `"期貨信託"`：

```python
excluded_keywords = ["ETF", "ETN", "權證", "反1", "正2", "槓桿", "反向", "特別股", "期信"]
```

### 4. 量比 clip 在 5 倍會砍掉最想抓的訊號 🟡

```python
day_df["vratio_feat"] = np.log(day_df["volume_ratio"].clip(lower=0.2, upper=5.0))
```

一檔爆量 20 倍的股票，跟爆量 5 倍的股票，在這裡分數完全相同。而「量能暴衝」正是「活躍」最強的訊號。

這是穩定度與敏感度的取捨——v3.0 選了穩定。若你的目的是抓「今天突然出事的股票」，這個 clip 上限應該放寬到 10 或 15。

### 5. 抓取時間增加約 6 倍 🟡

5 天 → 30 天，加上 `time.sleep(1.0)`，每次執行要多花約 1~2 分鐘，也提高被 TWSE 限流的機率。整合進每日 pipeline 時要留意。

### 6. 兩版共同的問題：沒有任何驗證 🔴

v2.1 和 v3.0 都沒有回答過「這個排名到底準不準」。這跟 analyzer v3.6 當初的問題一模一樣——**產出數字，但從不對答案**。

`tools/compare_predictors.py` 就是補這一塊。

## 三、「哪個選出的股票漲勢較高」

**這個問題兩支程式都沒有在回答。**

它們排序的是**活躍度**：成交值、量比、成交筆數、振幅。這四個指標裡沒有一個是報酬。而且：

> **振幅大 = 波動大 = 上下都可能。** 把振幅當成活躍度的正面指標，等於系統性地選中波動最劇烈的股票。對投資人來說，那同時是最容易大賺也最容易大賠的一批。

這也是我在 `paper_trading.py` 裡放 `active_equal` 對照組的原因——就是要實測「活躍 ≠ 會漲」。

### 用 `compare_predictors.py` 實測

```bash
python compare_predictors.py --days 90 --top-n 10 -o 版本比較.xlsx
```

它會做 walk-forward：在每個歷史時間點 T 分別用兩版選股，再看 T+1 / T+3 / T+5 的實際報酬，並與三個基準比較（全市場等權、隨機 N 檔、成交值最大 N 檔）。

**報告裡最重要的一欄是「超額報酬 t 值」**，不是平均報酬。原因：

- 同一期內全市場一起漲跌，各策略的絕對報酬高度相關。看到「v2.1 +0.21% vs 全市場 +0.04%」會誤以為有優勢，但那個差距可能遠小於它自己的波動。
- 逐期相減消掉大盤成分後，再除以標準誤，才知道它跟 0 分不分得開。**|t| < 2 就是「沒有可測量的優勢」。**
- t 值已針對重疊視窗修正。T+5 的相鄰期別重疊 4 天，觀察值不獨立；不修正的話，光是重疊就能讓 t 值虛增約 2.2 倍。我在「報酬與活躍度完全無關」的合成資料上驗證過：未修正時 T+5 的 t 值會膨脹到 3.3（看起來像顯著優勢），修正後降到 1.5（正確地判為無法區分）。

## 四、建議

| | 建議 |
|---|---|
| **選哪一版** | **用 v3.1**（v3.0 的修正版，見下節）。v2.1 的問題幾乎全部被 v3.0 修掉了，單獨去補 v2.1 沒有效益 |
| **已經幫你改好的** | ETF 4 碼漏洞（0050/0056）、`"期"` 誤殺、抓取起點永遠跳過今天、資料缺漏無提示 |
| **要知道的** | v3.0 的「預測」實際上是「近 3 日平均活躍度排名」，趨勢項貢獻 ≈ 0。名稱與行為不符，別被自己誤導 |
| **要實測的** | 跑 `compare_predictors.py --days 90`，看兩版的超額報酬 t 值。我預期兩版都會是 `\|t\| < 2`（與全市場無法區分）——如果真是這樣，那代表選股要靠的是別的東西，不是活躍度排序 |
| **不要做的** | 不要因為某一版這週選到飆股就認定它比較好。90 天大約只有 60 個測試期，有效獨立樣本數也差不多是這個量級，遠低於下結論所需的 100+ |

## 五、v3.1：兩版共同問題的修正

v2.1 的缺陷幾乎都被 v3.0 修掉了，所以**不建議回頭去補 v2.1**。但診斷過程中發現三個 **v3.0 也一起繼承或新引入**的問題，這些才需要處理，成果是 `tw_active_stocks_predictor_v3.1.py`。

| # | 問題 | 嚴重度 | 存在於 |
|---|---|---|---|
| 1 | 抓取起點寫死「昨天」，永遠不看今天 | 🔴 | v2.1、v3.0 |
| 2 | 4 碼規則擋不掉 0050 / 0056 | 🔴 | v3.0 |
| 3 | 名稱關鍵字「期」誤殺群益期(6024) | 🟠 | v3.0 |
| 4 | 資料缺漏的標的靜靜消失、無提示 | 🟡 | v2.1、v3.0 |

### 問題 1 最重要：篩選端比分析端落後一整個交易日

```python
current = datetime.date.today() - datetime.timedelta(days=1)   # v2.1 與 v3.0
```

TWSE 在收盤後（約 14:00 起）就會發布當日 MI_INDEX。所以你在週五 15:00 執行時：

- **篩選端**（predictor）：分析截至 **週四** 的活躍度，然後「預測週五」—— 但週五已經結束了
- **分析端**（analyzer v3.7）：用的是截至 **週五** 的資料

兩邊差一天。整合進 `tw_stock_pipeline_v1.1.py` 之後，這個落差會固定存在於每一次執行。

**v3.1 修法**：14:00 之後就從今天開始試抓。當日資料若尚未發布，TWSE 回傳 `stat != "OK"`，既有的 `None` 處理會自動往前跳，不會出錯。

```
盤中 10:00  → 起點 2026-08-27（當日資料還沒發布）
收盤後 14:30 → 起點 2026-08-28 ✓
收盤後 15:00 → 起點 2026-08-28 ✓
```
