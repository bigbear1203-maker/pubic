# 100 萬紙上交易模擬 — 操作手冊

**執行方式**：長期執行，沒有結束日期。你每執行一次就推進一個交易日。
**檢視節奏**：每週五自動另存一份週報快照（不會出清部位）。
**初始資金**：每個策略各 100 萬元（不是平分，是各自獨立，這樣報酬率可以直接比較）。

## 先講一件你一定要先知道的事

你的系統在 80 筆紀錄裡有 **79 筆是 `Wait`**，`model_quality` 零筆合格。

如果模擬程式只在 `Buy`/`Sell` 時出手，下週五你會看到「整週沒有任何交易、獲利 0 元」。那不是程式壞了，那是你的系統在誠實地說「我沒有把握」——但對你來說等於白做一週。

所以這個模擬器**同時跑 6 個各自獨立、各自都有 100 萬的虛擬帳戶**：

| 策略 | 選股規則 | 這一週要回答的問題 |
|---|---|---|
| `strategy_decision` | 只在 `Strategy_Decision=Buy` 時買進 | 你現行的規則整週會不會出手？ |
| `ev_decision` | 只在 `EV_Decision=Buy` 時買進 | v3.7 的影子規則會不會比較敢出手？ |
| `score_topn` | 綜合分數 >0 的前 5 名等權買進 | 三面向綜合分數有沒有用？ |
| `prob_topn` | 隔日上漲機率最高的前 5 名 | 機率模型有沒有用？ |
| `active_equal` | 活躍度前 5 名等權買進 | **活躍 ≠ 會漲**，這是對照組 |
| `cash` | 什麼都不做 | **最重要的對照組** |

最後那個 `cash` 不是湊數的。**任何策略如果贏不過「什麼都不做」，那個策略就是在付手續費買刺激。**

---

## ⚠ 前幾週的結果在統計上等於零

一週只有 5 個交易日，而且同一天所有股票會一起漲跌（大盤一動全動），有效獨立樣本數大約是 **1**。

**頭幾週的名次高低，幾乎完全由那幾週大盤的方向決定，不是由策略好壞決定。** 請不要在第一個週五看到某個策略賺 3% 就認定它有效，也不要看到 `strategy_decision` 賺 0 元就認定它沒用。

要看出策略差異，大致需要 **3 個月以上**（約 12 週、60 個交易日）。週報的價值在於「每週看一次、累積起來」，不是在於單一週的名次。

那為什麼還要做？三個實際理由：

1. **驗證流程跑得通** —— 資料抓得到嗎？訊號有出現嗎？下單邏輯對嗎？
2. **逼出實務問題** —— 例如：100 萬買不起一張台積電（一張約 242 萬）。這種事只有真的下單才會發現
3. **建立每天記錄的紀律** —— 這才是六個月後真正有價值的東西

## 0. 安裝與檔案擺放（第一次執行前做一次）

### 檔案怎麼放

**全部放同一個資料夾就好**，不需要建 `tools/` 子目錄（pipeline 兩種擺法都會自動找）：

```
D:\你的資料夾\
    tw_active_stocks_predictor_v2.1.py     ← 你原本就有的
    claude_stock_analyzer_v3.7.py          ← 新的（v3.6 可以留著不刪）
    tw_stock_pipeline_v1.1.py              ← 新的
    paper_trading.py                       ← 新的
    log_review.py                          ← 新的
    stock_analysis_log.xlsx                ← 你原本的紀錄，不會被動到
```

### 安裝套件

```bash
pip install yfinance pandas numpy requests openpyxl scikit-learn
```

`scikit-learn` 不是選用的 —— 沒有它就沒有 Random Forest 對照組，`Strategy_Decision` 會因為「雙模型未同時可用」永遠是 `Wait`。

### 確認能跑

```bash
python tw_stock_pipeline_v1.1.py
```

程式一開始會列出它找到的四支程式。如果有缺，它會一次告訴你缺哪幾支、該放哪裡，不會跑到一半才失敗。

### 紀錄檔會變成新的檔名

v3.7 的 Excel 欄位從 75 個增加到 101 個。因為欄位結構跟舊檔不一致，v3.7 會**自動另存**成 `stock_analysis_log_v3.7.xlsx`，**不會覆蓋**你現有的 `stock_analysis_log.xlsx`。

之後所有指令都是對新檔操作：

```bash
python log_review.py stock_analysis_log_v3.7.xlsx --write-back
python paper_trading.py step --date 2026-08-31 --log stock_analysis_log_v3.7.xlsx
```

`paper_trading.py` 的 `--log` 預設值就是這個檔名，所以通常不用特別指定。

## 每日操作

### 第一次：建立模擬（只做一次）

```bash
python paper_trading.py init --capital 1000000
```

### 之後：每個交易日收盤後執行一次

```bash
python tw_stock_pipeline_v1.1.py
```

**一定要 15:00 之後才跑。** 盤中執行的話，analyzer v3.7 會剔除未完成 K 棒、退回用前一交易日當基準，模擬器也拿不到當日的完整收盤價。

這支程式會依序做四件事：活躍股篩選 → 逐檔完整分析 → 模擬推進一天 → 回填前一日實際結果。

**沒有結束日期。** 想看目前狀況隨時可以：

```bash
python paper_trading.py report          # 印在畫面
python paper_trading.py status          # 只看現金與持股
```

### 每週五：自動存週報

週五執行時，pipeline 會**額外**另存一份 `模擬週報_YYYY-MM-DD.xlsx`。

這只是拍一張快照，**不會出清部位**——部位繼續留著，下週接著跑。這樣每週之間才有可比較的連續性。

### 想收尾時才結算

```bash
python tw_stock_pipeline_v1.1.py --settle
```

這會把所有部位以當日收盤價賣出（含賣出成本），印出完整結算報告。之後若要重開一輪：

```bash
python paper_trading.py init --state 模擬_第二輪.json --capital 1000000
```

## 模擬的成交規則（刻意保守，不美化）

| 項目 | 設定 | 為什麼 |
|---|---|---|
| 進場價 | **次日開盤價** | 訊號是 D 日收盤後才有的，不能用 D 日收盤價回頭買——那是作弊 |
| 買進成本 | 手續費 0.1425%×6折，最低 20 元 | 依你券商折扣調整 `--fee-discount` |
| 賣出成本 | 手續費 + 證交稅 0.3% | 來回約 **0.471%** |
| 零股 | **預設允許** | 100 萬買不起一張 2330。要只買整張請加 `--lot-only` |
| 停損 | 進場價 −7% 或 −2×ATR，取較近者 | 以**實際成交價**為基準，不是訊號當天的收盤價 |
| 停損檢查 | 收盤價 | 日 K 看不到盤中路徑。實際掛停損單出場價通常更差 |
| 單一標的上限 | 25% | 不讓一檔決定整週成績 |
| 同時持有 | 最多 5 檔 | |
| 期末 | 週五收盤全數出清 | 含賣出成本，所以是真正的落袋數字 |

想調整就在 init 時指定：

```bash
python paper_trading.py init --capital 1000000 \
    --top-n 5 --max-position-pct 0.25 --stop-loss-pct 0.07 --fee-discount 0.6
```

## 報告什麼時候可以看？

**隨時。** `report` 不用等到週五：

```bash
python paper_trading.py report                    # 印在畫面上
python paper_trading.py report -o 期中報告.xlsx   # 順便匯出 Excel
python paper_trading.py status                    # 只看現金、持股、待成交單
```

週五的差別是「有沒有真的出清」：

| | 週間（期中報告） | 週五 settle 之後（結算報告） |
|---|---|---|
| 標題 | 期中報告（尚未結算） | 結算報告 |
| 持股 | 還在，用最近收盤價估算市值 | 已全部變現成現金 |
| 報酬率 | 已扣「若現在出清」的估算成本 | 實際成交的真實數字 |
| 勝率 | 只算已平倉的部位 | 全部部位 |

⚠ **期中報告有兩欄要分清楚**：

- **期末權益** = 持股按收盤價估的市值，**還沒扣賣出時要付的手續費與證交稅**
- **若現在出清淨值** = 扣掉之後的真實落袋數字，`報酬率(%)` 也是用這個算的

兩者可以差 0.4% 以上。在一週報酬率本來就只有正負 1% 的尺度下，這個差距足以讓帳面的賺變成實際的賠——所以看期中報告時，請看「若現在出清淨值」那一欄，不要看「期末權益」。

## 部位怎麼進出（長期執行的關鍵）

短期跑一週看不出來，但長期執行時「什麼時候賣」比「什麼時候買」更決定成敗。出場規則分三類：

| 出場條件 | 適用 | 說明 |
|---|---|---|
| **跌出今日名單** | 排名型策略（`score_topn`／`prob_topn`／`active_equal`） | 這些策略的規則就是「持有當下的前 N 名」，跌出來就換掉 |
| **出現明確 Sell** | 訊號型策略（`strategy_decision`／`ev_decision`） | `Wait` 代表模型沒有意見，**不是**叫你賣。把 Wait 當賣出訊號會造成大量無謂來回 |
| **停損 / 時間停損** | 全部 | 跌破進場價 −7% 或 −2×ATR；或持有超過 10 天（可用 `--max-holding-days` 調整） |

⚠ **週轉率是長期執行最容易致命的一項。** 實測 4 週的模擬：

```
prob_topn    累計成本 48,146 元（本金的 4.81%），年化約 60.2%
score_topn   累計成本 47,105 元（本金的 4.71%），年化約 58.9%
active_equal 累計成本 10,661 元（本金的 1.07%），年化約 13.3%
```

排名型策略每天換股，一年的手續費就可以吃掉本金的 60%。報告會在累計成本超過本金 1% 時主動警示。**如果某個策略的報酬贏不過它自己的成本，那個規則就是在幫券商賺錢。**

## 週五該怎麼看報告

報告會列出六個策略的期末權益、報酬率、交易次數、勝率、累計成本、最大回落，並且直接告訴你**有幾個策略贏過「什麼都不做」**。

看的順序建議是：

1. **`strategy_decision` 到底有沒有出手？** 如果整週 0 筆，那就證實了診斷報告 §2.1 的判斷：這個規則在實務上等於關閉狀態。這是這次模擬最有價值的一個發現。
2. **累計交易成本吃掉多少？** 如果某策略報酬率落在 ±1% 內，那個數字基本上就是成本加雜訊，不是績效。
3. **`active_equal` 表現如何？** 它是拿來檢驗「活躍 ≠ 會漲」的。如果它大幅落後，那說明 pipeline 把最活躍的股票餵進來這件事本身就需要重新考慮。
4. **有沒有觸發停損？** 幾檔？跌多少？這會告訴你 −7% / 2×ATR 這組參數對台股活躍股是太鬆還是太緊。

**不要看的**：名次。一週的名次沒有意義。

## 這一週結束之後

模擬結束不代表工作結束。真正要累積的是 `log_review.py` 的統計：

```bash
python log_review.py stock_analysis_log_v3.7.xlsx --write-back
```

每天跑，累積到 **n ≥ 300**（大約 4～6 個月），再回頭看命中率的 Wilson 信賴區間下限有沒有超過 50%。那才是能拿來做投資決策的證據。

如果你想繼續模擬，直接開一個新的狀態檔就好：

```bash
python paper_trading.py init --state 模擬_2026Q4.json --capital 1000000
```

## 常見狀況

**Q：週一跑的時候說「log 中找不到這一天的分析結果」**
A：代表你那天沒有先跑 analyzer，或是跑的時候是盤中（基準日被記成前一天）。用 `python paper_trading.py status` 看目前狀態，補跑 analyzer 後再執行 step。

**Q：某些股票顯示「未成交（資金不足或取不到價）」**
A：正常。100 萬扣掉已持有部位後可能不夠買下一檔，或該檔當天停牌。模擬器不會為了湊滿部位而超額買進。

**Q：可以中途改參數嗎？**
A：技術上可以，但**不要**。改了參數，前面幾天的結果就不能跟後面比了。要改就開新的狀態檔重跑。

**Q：可以拿這個結果決定真的下單嗎？**
A：不行。一週的結果在統計上等於零，而且系統目前的 `model_quality` 零筆合格。這個模擬的用途是驗證流程與累積紀律，不是產生投資建議。
